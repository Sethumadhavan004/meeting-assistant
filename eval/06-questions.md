# 06 · Open questions

| # | question | status | notes |
|---|---|---|---|
| 1 | Is Bonsai's low % of bandwidth ceiling (~30% in manual runs) caused by a missing optimized AVX2 kernel for PQ2_0? | open | The binary does ship AVX2 CPU code (`ggml-cpu-haswell.dll`), so if it's a kernel gap, it's specific to the PQ2_0 format. The smoke test showed ~43% on a 40-token prompt. Real meetings (2026-10-25): 45% median vs 72–73% for the Q4 models, and prompt reading 3× slower and length-dependent (Q4). Pattern fits a format-specific kernel gap; not proven without a profiler or another PQ2_0 build. |
| 2 | Why is % of ceiling higher in the smoke test (Granite ~79%, Bonsai ~43%) than in the manual runs (~65%, ~30%)? | **mostly answered** (2026-10-25) | Real meetings, controlled settings: Granite 73%, Phi 72%, Bonsai 45% (median, think off). Higher than the manual runs, consistent with their confounds (power mode, Vulkan offload, mmproj); not separated per factor. Lower than the smoke test, consistent with the bigger KV cache from longer prompts. |
| 3 | Would Granite score differently at its recommended sampling (temp 1.0, top_p 0.95) instead of temp 0? | open, out of scope | Protocol fixes temp 0 for every model; see `02-protocol.md`. |
| 4 | Why did Bonsai's prompt speed fall from 30.7 to 12.6 tok/s across the think-on batch while generation speed stayed flat? | **answered** | Prompt length, not heat: the think-off batch (cooler CPU) gives the same tok/s at the same prompt length (~31 at 113 tokens → ~10.5 at 925). Bonsai's prompt processing gets slower per token as prompts grow; supports Q1 (no efficient batched kernel for PQ2_0). Granite stays flat (~45–67 tok/s) across the same prompt lengths, so the slowdown is Bonsai-specific. |
| 5 | Why does RAM delta rise across a batch, for both llama-server (peak working set 1.23 → 1.86 GB) and Ollama (delta 2.3 → 3.2 GB in Granite think-on)? | open | Not runtime-specific. Candidates: KV/compute buffers growing with longer outputs, allocator not returning memory, Windows memory compression. Test: same prompt 10× while logging the model process's own memory. |
